# macOS UI/UX review — 8 November 2026

Scope: welcome and populated notebook screenshots captured on macOS, plus implementation review of notebook, shell, runtime, outputs, history, checkpoints, diagnostics, settings, assistant, interchange, shortcuts, and accessibility. This is a heuristic review, not a completed interactive usability or accessibility qualification. Dialog geometry, VoiceOver, input composition, scrolling performance, light appearance, and multiple display scales still need live testing. Recommendations below are not implementation changes.

Design direction: a calm scientific workbench with a continuous editing canvas, quiet navigation, and blue reserved for the primary action or keyboard focus. Preserve the existing restrained dark palette and separation of notebook/history/checkpoints. Do not add marketing imagery, decorative gradients, or dashboard cards.

Information order: notebook identity and location; editable cells and outputs; execution state and actions; history and recovery on demand; assistant as secondary context.

Interaction direction: short panel transitions, subtle focus/selection changes, and clear pending-to-complete feedback. Respect Reduce motion; never animate code or output position while the user is reading.

P1 means a core task is blocked or materially confusing; P2 means a usability or hierarchy improvement; P3 means polish. These are review priorities, not measured incident severity.

## Preserve

The workspace already has a useful primary canvas, few colors, unobtrusive separators, syntax highlighting, native window controls, and separate history/checkpoint destinations. Preserve explicit assistant context approval, stale proposal handling, export-without-execution, and the distinction between closing a window and stopping a runtime. Existing behavior should be simplified in presentation without removing those guarantees.

## Recommended implementation sequence

1. Fix startup discovery and truthful source/loading/error states; add regression coverage for a Mac environment without a configured Python override.
2. Centralize platform shortcuts and menu labels; verify editor and IME interactions.
3. Simplify title bar, status hierarchy, cell focus styling, and welcome actions together.
4. Improve settings/provider setup and assistant context/proposal hierarchy.
5. Improve history/checkpoint recovery and export explanations, then run keyboard, VoiceOver, sizing and large-notebook qualification.

Do not assign a numeric UX score from this review: most surfaces were inspected in source rather than exercised live. Capture welcome, editing, running, error, history, checkpoint, settings, assistant, export and recovery states in light and dark appearances before marking them qualified.
