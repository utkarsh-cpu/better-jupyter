# Radeon 8060S WSL test environment

The target is `Ubuntu-24.04` on WSL 2, with the Radeon 8060S (`gfx1151`) in
the Ryzen AI Max+ 395. The isolated interpreter is
`/home/utkarsh_kaushik/.venvs/kernelledger-gpu/bin/python`.

The environment uses PyTorch 2.12.0+rocm7.14.0, ROCm 7.14.0 host libraries
and architecture-specific kernels, NumPy 2.5.2, and ROCDXG 1.2.1. ROCDXG
routes Linux GPU computation through the Windows GPU driver and `/dev/dxg`.
The setup follows [AMD's ROCm installation instructions](https://rocm.docs.amd.com/en/docs-7.14.0/install/rocm.html#install-rocdxg-and-amd-smi-for-wsl)
and [ROCDXG's compatibility table](https://github.com/ROCm/librocdxg#user-content-wsl-compatibility-matrix).

From this repository in PowerShell:

```powershell
wsl -d Ubuntu-24.04 -u root --exec bash '/mnt/c/Users/UTKARSH KAUSHIK/Documents/Projects/KernelLedger/scripts/setup-wsl-gpu.sh' system
wsl -d Ubuntu-24.04 --exec bash '/mnt/c/Users/UTKARSH KAUSHIK/Documents/Projects/KernelLedger/scripts/setup-wsl-gpu.sh' environment
wsl -d Ubuntu-24.04 --exec bash '/mnt/c/Users/UTKARSH KAUSHIK/Documents/Projects/KernelLedger/scripts/test-wsl-gpu.sh' artifacts/my-wsl-checkpoint-test
```

Use a fresh artifact output directory for each run. The system phase installs
Ubuntu dependencies and the ROCDXG runtime. It switches Ubuntu's mirror URLs
to HTTPS and saves their original configuration under `/var/backups/` because
HTTP connections stalled on this machine. The environment phase runs as the
normal Ubuntu user. No Windows driver or Linux kernel is installed by these
scripts.

The test checks actual GPU matrix multiplication, tensor bytes and shared-view
restoration, then saves a model, gradients, Adam optimizer, StepLR scheduler,
training mode, RNG, step and cursor. After the donor exits, a fresh process
imports the exported snapshot and compares its next loss and model parameters
with the donor's expected result. Files remain in the selected artifact
directory, including `export/`, `recipient/`, and `result.json`.

This tests portable application-state checkpoints. A WSL DXG target does not
qualify amdgpu/KFD/CRIU native process snapshots. Small-model continuation also
does not establish distributed or large-model performance guarantees.

On 2026-10-07 the GPU matrix multiplication, tensor/view checkpoint round-trip,
and donor-exit training continuation all passed. The targeted suite passed 40
tests and the full regression suite passed all 110 tests in 43.13 seconds.
The small-model snapshot stored 38,358 bytes, with capture taking 5.98
seconds and restore 4.62 seconds. Artifacts were written through the Windows
drive mount, so these timings include that filesystem overhead. The initially
reported NUMA library warning was resolved by installing `libnuma-dev`; a fresh
GPU probe then passed without the warning.

See [the exact stack and test evidence](qualification/wsl-8060s-portable-2026-10-07.json)
and [the saved benchmark](../../benchmarks/gpu/wsl-8060s-portable-2026-10-07.json).

## Native process checkpoint feasibility

On 2026-10-08 an active GPU process successfully computed a tensor reduction
and its open device handle was `/dev/dxg`. `/dev/kfd`, the amdgpu kernel module,
and KFD topology were absent. The WSL kernel has `CONFIG_CHECKPOINT_RESTORE=y`,
but this generic process support does not supply the vendor driver mechanisms
for saving GPU allocations, queues and contexts. CRIU was absent and had no
installation candidate in the configured Ubuntu repositories.

The [AMD CRIU plugin](https://github.com/checkpoint-restore/criu/blob/criu-dev/Documentation/criu-amdgpu-plugin.txt)
requires checkpoint-capable amdkfd/amdgpu. This target therefore reports native
GPU process snapshots as **unsupported**, rather than merely awaiting a
successful test. No native image was created and no resume was attempted.
Installing CRIU alone cannot replace the missing driver interface. A separate
native Linux target with a qualified GPU/driver/plugin stack is needed to test
native GPU continuation; the 8060S's portable support does not establish its
native CRIU support.

The [probe evidence](qualification/wsl-8060s-native-2026-10-08.json) records
the actual runtime, device handles and kernel configuration. Repeat it with:

```powershell
wsl -d Ubuntu-24.04 --cd '/mnt/c/Users/UTKARSH KAUSHIK/Documents/Projects/KernelLedger' --exec /home/utkarsh_kaushik/.venvs/kernelledger-gpu/bin/python scripts/probe-wsl-native-gpu.py
```
