# KernelLedger plan, version 2

**Status:** Superseded on 2026-10-03 by [plan version 3](../PLAN.md).

**Archived summary:** A local notebook runtime with an owned source format, a supervisor that is the only writer of history, a Python worker, typed checkpoints, and a CLI. Version 3 keeps that shape and corrects the checkpoint design (function source capture, restore globals, immutable cycles, tagged encoding, blob publish), the worker interpreter rule, the lock rule, and output handling.

The text below is the version 2 plan as it stood when version 3 replaced it.

# KernelLedger plan

| | |
| --- | --- |
| Plan version | 2 |
| Date | 2026-10-03 |
| Status | Superseded by version 3. |
| Supersedes | [Plan version 1](v1.md) |

Version 2 is a local notebook runtime. A notebook is a directory of source files. A supervisor process is the only writer of execution history. A worker process runs Python. A checkpoint restores a supported object graph into a new worker.

Plan version 1 hosted this product inside JupyterLab, tracked source through Jupytext, evaluated dill for checkpoints, and left process resume to a Linux CRIU experiment. Those choices are archived with version 1. This document replaces them.

## 1. Guarantees

| Operation | Guarantee |
| --- | --- |
| Open source | Recover code, Markdown, raw cells, cell ids, order, intentional metadata, and attachments from the tracked files alone. |
| Inspect a run | Show the recorded source, events, and folded outputs. Inspection executes nothing. |
| Replay a run | Execute recorded source, in recorded order, in a new worker. Report environment differences. Identical results are not part of the guarantee. |
| Restore a checkpoint | Load the published object graph into a new worker. Names the checkpoint could not represent stay unset, and the report lists them. |
| Continue | Restore a checkpoint, then run new work in a new session. Earlier sessions stay immutable. |

A recorded history is not the live worker namespace. A checkpoint is not a snapshot of the process. Replay and continue repeat whatever side effects the source performs. Neither operation restores a socket, a remote service, or an external file that the checkpoint did not itself store.

Four checkpoint outcomes exist, and the product uses these words only for these meanings:

| Outcome | Meaning |
| --- | --- |
| Complete | Every user binding was stored, the worker was idle, and no extra threads were running. |
| Partial | The stored graph is consistent. One or more bindings were left out, and each omitted binding is named. |
| Refused | Nothing was published. The worker was busy, extra threads were running, or a limit was exceeded. |
| Failed | A crash or I/O error occurred before publish. No checkpoint id exists for that attempt. |

## 2. Out of scope

Version 2 ends at the guarantees above.

- JupyterLab, ipykernel, Jupytext, nbdime, nbclient, and papermill are not runtime dependencies. `.ipynb` import and export are converters.
- IPython magics, shell escapes, widgets, and kernel subshells are not part of the worker protocol.
- Pickle, dill, and cloudpickle are not checkpoint formats.
- Process checkpoint tools, including CRIU and DMTCP, are not a delivery phase.
- Live multi-user editing is not a delivery phase. Collaboration is Git on the source files plus an explicit bundle or published checkpoint descriptor.
- The product does not install packages, fetch datasets, or reproduce a conda, uv, or CUDA environment. It records the interpreter it actually ran and reports drift.
- A graphical editor is not required for any phase to be complete.

## 3. System shape

```text
CLI  --->  Supervisor  --->  Worker  --->  user code
              |
              +--> ledger.sqlite
              +--> blobs/<sha256>
```

The CLI talks to the supervisor. The supervisor owns the notebook directory lock, the ledger, and the blobs. It spawns the worker, sends one execution at a time, and records events. The worker cannot open the ledger.

The supervisor stays alive between CLI commands so the worker namespace survives. The first command starts it. Later commands connect to it. `kl stop` shuts both processes down. When the supervisor exits, the live namespace is gone. Checkpoints already published remain on disk.

On Windows and Unix the supervisor is a normal child process listening on `127.0.0.1`. Its port and a random authentication token live in `.kl/`. Every command presents the token. A lock file records the supervisor pid. A dead pid means the lock is stale, and the next command may take over. It marks any in-flight execution `incomplete` and closes that session as `crashed`.

## 4. Files

```text
analysis/                          # tracked by Git
  notebook.json                    # id, order, metadata, attachment names
  cells/
    <cell-id>.py                   # code
    <cell-id>.md                   # Markdown
    <cell-id>.raw                  # raw cell text
  attachments/
    <cell-id>/<filename>           # bytes referenced by a cell

.kl/                               # local runtime state, gitignored
  ledger.sqlite
  blobs/<sha256>
  tmp/                             # unpublished checkpoint files
  supervisor.json                  # pid, port, token path
  token                            # secret used by local CLI connections
```

Git tracks `notebook.json`, `cells/`, and `attachments/`. Git ignores `.kl/`. A later publish step may also track a checkpoint descriptor. Descriptors point at hashes. They are not a second execution log.

`notebook.json` is the manifest because the Python standard library can read and write JSON. The writer uses stable key order, one cell object per line, a trailing newline, and UTF-8. Cell source stays in its own file so a one-cell edit is a one-file diff.

## 5. Document format

`notebook.json` schema 1:

```json
{
  "schema": 1,
  "id": "8f1c0c3e-7b2a-4e1d-9c0a-6d5e4f3a2b10",
  "metadata": {},
  "cells": [
    {"id": "intro", "type": "markdown", "attachments": ["diagram.png"]},
    {"id": "load", "type": "code"}
  ]
}
```

| Field | Rule |
| --- | --- |
| `schema` | Integer. The supervisor refuses a newer schema than it knows. |
| `id` | Notebook UUID, lowercase, assigned at `kl init`. Stable across rename and clone. |
| `metadata` | Intentional notebook metadata. Execution counts, outputs, and timing never go here. |
| `cells` | Order is the order of this array. |
| `cells[].id` | Filename stem. Pattern: one to 64 characters, `[A-Za-z0-9_-]`, first character alphanumeric. Unique in the file. |
| `cells[].type` | `code`, `markdown`, or `raw`. |
| `cells[].attachments` | File names only. No path separators. Bytes live under `attachments/<cell-id>/`. |

Reserved Windows device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1` through `COM9`, `LPT1` through `LPT9`) are rejected as cell ids.

Cell files are UTF-8 without a BOM. The canonical newline is `\n`. The source hash is SHA-256 of the canonical UTF-8 bytes. `kl import` writes canonical files. `kl doctor` reports a file that still contains a BOM or `\r`. Execution sends the canonical text to the worker.

A cell id is minted when a cell is created. Import keeps an `.ipynb` cell id when it already matches the grammar. Otherwise import mints an id and stores the original under `metadata.kernelledger.imported_ids`. Opening a notebook never rewrites ids. Duplicate or missing ids are a doctor error. `kl doctor --repair-ids` is the explicit repair: it mints replacement ids, prints the map, and rewrites the manifest.

Deleting a cell removes it from `notebook.json` and deletes that cell file. Blobs already stored for earlier executions stay. History can still show the source that ran.

Copying a project directory copies the notebook id. `kl doctor` reports two working copies that share an id when it can see a configured sibling, and it always reports the id. `kl retarget` assigns a new notebook id when the user means to make an independent notebook. It does not run as part of open.

Attachments are ordinary files in Git. Markdown source refers to them by file name. The importer writes image and other notebook attachments here as decoded bytes.

## 6. Worker

The worker is a Python subprocess using the same interpreter version as the supervisor. User code runs on the worker main thread, in a dedicated globals dict, with `__name__` set to `"__main__"`. The filename passed to `compile` is the cell path, so tracebacks point at the cell file.

If the cell's last statement is an expression, the worker executes the preceding statements and evaluates that expression. The value is emitted as a result when it is not `None`. Display output is whatever user code passes to `display()`, which the worker installs in the user globals.

The worker redirects `sys.stdout` and `sys.stderr` into protocol events. Bytes written straight to the process pipes, bypassing those objects, are recorded by the supervisor as stdout or stderr events with `"capture": "pipe"`.

`input()` emits a stdin request and waits for the supervisor to deliver the reply. A non-interactive replay fails that execution with an error that says input was required, unless the replay was given a recorded reply to reuse.

Interrupt sends a control message. The worker interrupts the main thread. A tight C extension may keep running until it returns to Python. The execution then ends as `interrupted`.

Names beginning with `_kl_` are reserved for the worker. The checkpoint walk skips them. User bindings named `__builtins__` are skipped and listed as excluded.

The worker does not implement magics or `!` commands. Imported notebook source that contains them is preserved and then fails as Python if it is run.

## 7. Protocol

Control messages travel on a localhost socket between supervisor and worker. Framing is a 4-byte big-endian length followed by a UTF-8 JSON object. A binary frame is a JSON header with `kind`, `sha256`, and `byte_size`, then exactly that many raw bytes. The supervisor writes those bytes into the blob store and records the hash. The worker never receives a path inside `.kl/`.

Protocol schema is an integer on every message. A peer refuses a newer schema.

Supervisor to worker:

| Message | When |
| --- | --- |
| `execute` | `{exec_id, cell_id, source_sha256, source}`. Sent only after the ledger row exists. |
| `stdin_reply` | Response to a worker `stdin_request`. |
| `interrupt` | User asked to stop the in-flight execution. |
| `checkpoint` | Worker is idle. Asks for a graph walk. |
| `restore` | Asks the worker to install a graph the supervisor has already validated. |
| `shutdown` | Exit cleanly. |

Worker to supervisor:

| Message | When |
| --- | --- |
| `ready` | Process is up and the user namespace is empty, or restore finished. |
| `stdout`, `stderr` | Captured text, or a blob hash when the chunk is large. |
| `display` | `{mime, display_id?, inline? , blob_sha256?}`. |
| `display_update` | Replaces the visible item with the same `display_id`. |
| `result` | The cell's final expression. |
| `error` | `{ename, evalue, traceback}`. |
| `clear` | `{wait: bool}`. |
| `stdin_request` | `{prompt, password}`. |
| `status` | `idle` after the execution's events are finished. |
| `checkpoint_offer` | The walked graph, or a refusal reason. |
| `restore_result` | Bindings installed, and any that failed during load. |

Inline text and inline JSON payloads are limited to 64 KiB. Larger payloads are binary frames and blobs.

The supervisor writes the `execute` row with status `queued` before it sends `execute`. Status moves to `running` when the worker accepts it, then to `ok`, `error`, `interrupted`, or `aborted`. If the worker or supervisor dies after `queued` or `running`, the next supervisor start sets that row to `incomplete`.

`cell_id` is null for source the user submitted outside a cell. The row still stores the exact source hash. Inspection labels those executions unattributed.

One execution is in flight per supervisor. A second `execute` waits in the supervisor queue, in the order the commands were accepted. The ledger ordinal is that acceptance order.

## 8. Ledger

SQLite is the only live history. `PRAGMA user_version` is the ledger schema. The supervisor uses WAL mode and is the only process that writes the file. Export builds JSONL from a query. Nothing in the running system appends to a JSONL file.

Schema 1 tables:

| Table | Role |
| --- | --- |
| `sessions` | One worker lifetime. Columns include notebook id, parent session, restored checkpoint id, state (`running`, `closed`, `crashed`), start and end timestamps, Python version, platform, cwd, and the recorded environment object. |
| `executions` | One row per accepted execution. `exec_id`, `session_id`, monotonic `ordinal`, nullable `cell_id`, `source_sha256`, status, start, end. Unique `(session_id, ordinal)`. |
| `events` | Append-only. Primary key `(exec_id, seq)`. `kind`, timestamp, `payload_json`, nullable `blob_sha256`. |
| `checkpoints` | Published checkpoints only. Id, session, boundary execution id, `complete` or `partial`, manifest blob hash, timestamp. |
| `blobs` | `sha256`, `byte_size`, `media_type`. |
| `pins` | Named pins pointing at checkpoint ids the user chose to keep. |

Timestamps are UTC RFC 3339. Order comes from `ordinal` and `seq`, not from the clock.

The environment object records the Python version, the implementation name, `platform.platform()`, the worker cwd, and the worker executable path. Process environment variables are omitted unless the project contains `.kl/env-allowlist`, a JSON list of variable names. Values for those names are stored. The default file is absent.

Blob bytes are written, fsynced, and then referenced by a committed ledger row. A blob hash is the address. Rewriting a blob path in place is not allowed.

`kl gc` deletes blobs that no execution, event, checkpoint, or pin references. It is explicit. Startup deletes `.kl/tmp` entries left by a previous process. Startup does not run `kl gc`.

## 9. Visible outputs

Events are the record. The view folds them in `seq` order:

- `stdout`, `stderr`, `display`, `result`, and `error` append an item.
- `display_update` replaces the latest item with the same `display_id`.
- `clear` drops the current items. `wait: true` defers the drop until the next output item, matching the usual notebook animation behavior.
- Folding never deletes events.

`kl show` prints the folded view. `kl show --events` prints the raw sequence. An execution whose source hash differs from the current cell file is labeled with both hashes.

## 10. Checkpoints

A checkpoint is taken between executions, while the worker is idle. `checkpoint` during a run is refused. Nothing is published.

Before walking memory, the worker lists threads. Any thread besides the main thread and the worker's own protocol thread refuses the checkpoint with reason `background_threads`. The refusal is an event on the session. There is no checkpoint id.

The walk starts at the user globals. It skips `_kl_` names and `__builtins__`. Every other binding is in the offer or in the excluded list.

Supported object kinds in schema 1:

| Kind | Stored as |
| --- | --- |
| `None`, bool | JSON literal |
| int | JSON number inside the safe integer range, otherwise a decimal string |
| float | JSON number. `NaN`, `Infinity`, and `-Infinity` are strings |
| str | JSON string, or a blob when it exceeds the inline limit |
| bytes | blob hash |
| list, tuple | array of values or `$ref` objects. The kind distinguishes tuple from list |
| dict | string keys only. A dict with any non-string key is unsupported as a whole |
| set | array of members. Membership is the meaning. Order is not |
| datetime | UTC ISO 8601 string |
| UUID | canonical string |
| import | module name and qualname. Restore imports it |
| function, class | source text captured at checkpoint time, plus closed-over values |
| instance | class reference plus `__dict__`, for classes defined in the notebook that use `__dict__` and do not use `__slots__` |
| ndarray | optional codec, present when NumPy is installed in the worker |
| table | optional codec for a pandas DataFrame, stored as named typed columns |

The graph uses object ids. The first time the walk sees an object, it assigns an id. Later encounters emit `{"$ref": "<id>"}`. Cycles are references back to an id already assigned. The loader creates every object, then fills references.

A function or class is stored as the source text of its definition, not as a lookup into the current cell file. The cell may have changed since the object was created. Restore executes that saved source in a fresh module and rebinds closures from the graph. An imported callable is stored as an import reference. Restore imports it. A failed import or a failed source exec puts that binding on the restore report and leaves the name unset.

Instances store the class reference and the instance `__dict__`. The checkpoint does not call `__getstate__` or `__reduce__`. An object with `__slots__` and no `__dict__`, or an instance of a class the walk cannot represent, is unsupported.

An imported module binding is an import reference. Restore imports the module again. Assignments made to that module's globals after import are outside the graph. The manifest records `imports_reimported: true`.

If any object reachable from a binding is unsupported, that binding is excluded. A field is never dropped while the parent is reported as saved. Other bindings stay. A shared child that is unsupported excludes every binding that reaches it. Each excluded entry has the binding name, the Python type name, the path that failed, and a reason:

| Reason | Meaning |
| --- | --- |
| `unsupported_type` | No codec for this object |
| `unsupported_key` | A dict key is not a string |
| `missing_codec` | The type is known and its optional codec is not installed |
| `unimportable` | The module or qualname could not be imported at restore |
| `source_exec_failed` | Saved function or class source failed during restore |
| `resource` | File, socket, generator, thread, task, or similar live resource |

NumPy arrays use a codec registered only when NumPy imports. The payload is dtype name, shape, and a raw little-endian blob. An array whose dtype the codec does not list is `unsupported_type`. Object arrays are `unsupported_type`. Restore checks the dtype, shape, and hash, then rebuilds the array.

A DataFrame codec, when pandas imports, writes each column through the same scalar and array rules. The restore target is a DataFrame when pandas imports in the new worker. When pandas is absent, restore leaves the name unset and reports `missing_codec`. It does not substitute a different object under the same name.

The standard-library `random.Random` state is a tuple of supported values. A complete or partial checkpoint includes it under a reserved binding `_kl_random` that is hidden from the user namespace and applied on restore. NumPy generator state is included only through the NumPy codec, the same way. Other generators in user code are ordinary bindings and follow the support rules. `PYTHONHASHSEED` and RNGs inside other libraries are not captured.

Limits, initially 100,000 objects and 2 GiB of new payload, refuse the checkpoint when exceeded. A refused checkpoint is not partial. Partial means named bindings were excluded and every stored binding is complete.

Publish sequence:

1. Worker sends `checkpoint_offer`.
2. Supervisor writes new blobs under `.kl/tmp/<attempt-id>/` and fsyncs them.
3. Supervisor hashes the manifest and, in one SQLite transaction, inserts blob rows and the checkpoint row.
4. The transaction commit is the moment the checkpoint exists.
5. Supervisor deletes the temp directory.

A crash before commit leaves no checkpoint id. The next start removes the temp directory. A crash after commit leaves a valid checkpoint. The manifest blob is the manifest. The ledger row is the publication record.

Python version and the codec names and versions are fields in the manifest. Restore refuses a manifest whose `schema` is newer. It refuses a Python major.minor that differs, unless the user passes an explicit override flag. The override is recorded on the new session. Platform differences are reported and do not, by themselves, refuse restore.

## 11. Restore, replay, and continue

**Restore** starts a new worker and a new session whose `restored_checkpoint_id` is set. The supervisor checks manifest hashes and blob presence, sends `restore`, and records `restore_result`. Missing blobs refuse the restore. The new namespace contains the restored bindings. Names that failed are absent and listed.

**Replay** starts a new worker with an empty namespace and executes stored source in ordinal order. It uses the stored source bytes, including source for cells that were later edited or deleted. It records a new session. The parent session id links back to the session being replayed. Environment fields that differ are printed before the first cell runs. Replay of an execution that issued `stdin_request` uses the stored reply only when the user passes `--reuse-input`. Otherwise that execution ends as an error and replay stops.

**Continue** is restore followed by ordinary new executions. New executions append to the new session. The restored session is unchanged.

**Inspect** reads the ledger and blobs. It does not start a worker.

Replay and continue run user source. Writes, deletes, and network calls in that source happen again. The CLI states that when the command starts.

## 12. Import, export, and bundles

`kl import` reads an `.ipynb` with the standard-library JSON parser.

- Code, Markdown, and raw cells become cell files.
- Cell ids are kept when legal, otherwise minted, with the original saved in metadata.
- Attachments are base64-decoded into `attachments/`.
- Outputs and execution counts are not written into the tracked files.
- With `--keep-outputs`, those outputs become a synthetic session labeled `imported`. Imported events have no worker and no claim that this runtime executed them. Their source hash is the imported cell source.

`kl export` writes an `.ipynb` from the current source plus a selected session's folded outputs. Each code cell records the source hash that produced the attached outputs. When that hash differs from the current cell file, the exported cell metadata carries both hashes and `kernelledger.output_mismatch: true`.

`kl bundle export` writes a directory or zip:

```text
bundle/
  MANIFEST.json          # schema, notebook id, session ids, checkpoint ids, file hashes
  notebook/              # notebook.json, cells, attachments
  ledger.jsonl           # sessions, executions, events, checkpoint rows for the selection
  blobs/<sha256>
```

The manifest lists every blob the selection references. External things the notebook merely named, such as a CSV path the source opened, are listed under `external` from paths the user passed in. The bundle does not try to discover every file the source touched.

`kl bundle show` prints ids, statuses, excluded bindings, and hash mismatches. It does not execute source and does not restore.

`kl bundle import` copies blobs and ledger rows into a local `.kl/` after hash checks. Restore and replay of that data still require the trust flag in section 14.

A published Git descriptor is a small JSON file under `checkpoints/<checkpoint-id>.json` containing the checkpoint id, manifest hash, blob hashes, status, and excluded names. `kl publish` writes it. Payloads stay in `.kl/` or in a bundle. `kl fetch` reads a descriptor and reports every missing blob. A descriptor is a selected snapshot pointer, not a live log.

## 13. Git

Independent edits to different cell files merge as ordinary text. Reordering cells changes `notebook.json`. Two reorders can conflict in that file. Two edits to the same cell file conflict in that file. The resolution is a normal Git resolution. `kl doctor` after a merge checks ids, file presence, attachment names, and canonical newlines.

The runtime does not install a custom merge driver in version 2.

Concurrent supervisors on one notebook directory are rejected by the lock. Two notebooks are two directories and two ledgers. There is no merged execution timeline.

## 14. Security

The checkpoint format is JSON plus raw blobs. Loading scalars, collections, arrays, and tables does not call user-defined reduce functions.

Restore executes saved function and class source. Replay executes cell source. Both are code execution. `kl restore`, `kl replay`, `kl continue`, and `kl bundle import` of a bundle that will be restored refuse to run without `--trust` when the data was not created by this local ledger. Data this supervisor just wrote can be restored by the same user without an extra prompt. `kl show` and `kl bundle show` never need `--trust`.

The local socket accepts commands only with the token from `.kl/token`. The file is created with the most restrictive permissions the platform allows.

Checkpoint values are the user's variables. A bundle can contain secrets that were in those variables. Export prints that warning. The product does not claim to find every secret. Users can put names in `.kl/checkpoint-denylist` to force those bindings into the excluded list.

Imported `.ipynb` outputs are data. They are shown as outputs. They are not executed.

Commands that need a live namespace fail with a clear error when the supervisor is down, and they do not invent an empty success. Restore is the way back to a saved namespace.

## 16. Compatibility

| Artifact | Version field | Rule |
| --- | --- | --- |
| `notebook.json` | `schema` | Refuse newer. Migrate older with an explicit `kl migrate` once an older schema exists. |
| Ledger | `PRAGMA user_version` | Same rule. |
| Protocol | `schema` on each message | Refuse newer. |
| Checkpoint manifest | `schema` | Refuse newer. |
| Bundle `MANIFEST.json` | `schema` | Refuse newer. |

Schema 1 is the first schema. There is no silent best-effort load of an unknown field that changes meaning. Unknown fields in a known schema are preserved on notebook metadata and ignored on runtime messages only when the schema number matches and the field is outside the required set. Required fields that fail validation refuse the file.

The implementation baseline is Python 3.11 or newer, on Windows and Linux, using the standard library for the supervisor, worker, ledger, JSON, hashing, and subprocesses. NumPy and pandas are optional and are imported only by their codecs.

## 17. Phases

Dates stay unset until a prototype has measured checkpoint time and blob growth on a representative notebook.

| Phase | Deliverable | Completion evidence |
| --- | --- | --- |
| 1. Source | `notebook.json`, cell files, attachments, import/export, doctor | A second clone of the tracked files alone preserves ids, order, Markdown, raw cells, metadata, and attachments. Running a cell does not modify tracked files. A non-canonical newline fails doctor. |
| 2. Ledger | Supervisor, worker, protocol, sessions, events, blobs, log/show | The same cell run twice keeps two executions and both outputs. Editing the cell afterward still shows the historical source. A killed supervisor reopens with the in-flight execution `incomplete` and without a corrupt ledger row. Binary display payloads survive. Inspection does not start a worker. |
| 3. Checkpoints | Graph walk, publish rule, restore | A new worker receives supported aliases and cycles. An unsupported binding is named and a partial checkpoint says partial. A busy worker and a worker with an extra thread publish nothing. A crash during publish leaves either no checkpoint id or a checkpoint whose hashes match. A restored class is the class produced from the saved source. |
| 4. Replay and bundles | Replay, continue, bundle export/import, publish descriptor | Replay uses historical source, including a deleted cell's stored source, and prints environment drift. Continue appends to a new session and leaves the old session unchanged. A bundle contains every referenced blob. Import of a tampered blob fails the hash check. `kl gc` removes only unreferenced blobs and keeps pinned checkpoints. |
| 5. Shared descriptors | Descriptor fetch, denylist, allowlist, trust flag | A second clone can read a published descriptor, list missing blobs, and merge a cell-file edit with Git. Restore of a fetched bundle requires `--trust`. A denylisted name is excluded. |

Phase 3 is done when the builtin kinds restore correctly. The NumPy codec is part of phase 3 when NumPy is installed, and is skipped with `missing_codec` when it is not. The DataFrame codec is part of phase 3 under the same rule.

## 18. Validation

Representative fixtures:

- Code, Markdown, raw text, and an attachment.
- Two names bound to one list, and a self-referential list.
- Integers outside the JSON safe range, and non-finite floats.
- A function and a class defined in a cell, then a later edit to that cell before restore.
- An import binding.
- A NumPy array when NumPy is present, and a DataFrame when pandas is present.
- An open file and a socket in the user namespace.
- A thread started by user code.
- A cell that calls `display` twice with one `display_id`, then `clear`.
- A cell that calls `input()`.
- A large binary display.
- Two executions of one unchanged cell.

Required scenarios:

| Scenario | Result |
| --- | --- |
| Run a cell | Tracked files are unchanged. Ledger gains an execution and events. |
| Edit, delete, and reorder after a run | Historical execution still resolves its source blob and original cell id. |
| Identical source, two runs | Two outputs remain. |
| Second supervisor on the same directory | Rejected while the lock is live. |
| Kill the supervisor mid-run | Reopen shows `incomplete`. No partial event sequence is marked `ok`. |
| Kill the supervisor after blobs are written and before the checkpoint transaction commits | That attempt has no checkpoint id. |
| Restore a complete checkpoint | Aliases compare equal with `is`. Cycles terminate. |
| Restore after the defining cell was edited | The restored function matches the checkpointed source, not the edited file. |
| Unsupported binding | Checkpoint status is partial and names the binding. |
| Extra thread or in-flight run | Refusal, no checkpoint row. |
| Round-trip an array or table | Values match. A codec that cannot preserve values fails the test rather than publishing. |
| `kl show` | No worker process is created. |
| Replay | Stored source runs in order. Drift is printed. Side effects are allowed because the command was replay. |
| Bundle | Every hash in the manifest is present. An edited blob is rejected. |
| `kl gc` | Unreferenced blobs disappear. Blobs referenced by a pin remain. |
| Text-only clone | Ids and attachments match without any `.kl/` directory. |

Measure, on a notebook that holds a few hundred megabytes of arrays, the time to checkpoint, the time to restore, the size of new blobs, and the time the worker spends inside the checkpoint walk. Those numbers decide later incremental checkpoints. Version 2 does not specify an incremental format. A reused variable name or a matching cell hash is not evidence that an object was unchanged.

## 19. Deferred choices

These are real product choices. They are not hidden inside a phase exit.

| Choice | When it has to be made |
| --- | --- |
| Incremental checkpoints | After phase 3 measurements. A new plan version specifies the format. |
| Graphical editor | After the CLI completes phases 1–4. The editor is a client of the supervisor. |
| Remote blob storage | After local bundles work. Descriptors already refer to hashes so the payload location can change. |
| Installing dependencies for replay | Only if replay should do more than report drift. |
| Codecs for GPU tensors, model objects, and open-file recreation | Each codec is an explicit addition with a round-trip test. |
| Custom Git merge driver | Only if manifest conflicts become a practical problem. Cell source conflicts are ordinary text conflicts. |

## 20. What version 2 keeps from version 1

Version 1's guarantee split is the product. History, object restore, and process resume are different operations, and version 2 keeps the first two. Process resume is removed rather than postponed.

Version 1's publish rule is the crash rule: durable payloads first, then one commit point, then a visible id. Version 2's commit point is the SQLite transaction that inserts the checkpoint row.

Version 1's recording rule is the recording rule: persist the request before execution, key it by request id, keep events after a clear, and label missing cell attribution.

The implementation that carries those rules is the supervisor, the worker, and the typed graph in this document.
